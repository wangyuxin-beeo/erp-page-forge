# DSH 插件使用指南（1.6.2）

ERP Page Forge 可以在 DSH 对话中调用，也可以通过本机 Forge Studio 网页操作。推荐先在对话中描述开发任务，需要查看原型和产物时再打开 Studio。

## 安装后先做什么

1. 在 DSH 的插件管理中安装并启用 `dsh-erp-page-forge-1.6.2.tgz`。
2. 在自己的 DSH 中配置可用的模型，并在当前会话选择它。插件使用每位使用者自己的模型和凭据，不携带作者的密钥。
3. 使用截图识别、原型还原时，所选模型必须支持图片输入。采集网页还需在本机准备 Playwright 和可启动的 Chrome/Edge，安装方法见 [原型采集说明](web-capture.md)。

插件安装后不会自动弹出网页，也没有独立的 DSH 侧边栏面板。需要在对话里下达任务，或让 AI 启动 Studio。

## 方式一：在 AI 对话中使用

直接在 DSH 对话里说明任务。AI 会调用已启用的插件工具，返回执行结果、文件路径和可用的预览地址。用户不需要手写工具名或 JSON，也不必先打开 Studio。

### 生成一个 ERP 页面

```text
使用 ERP Page Forge 插件，生成销售订单列表页。
字段：订单号、客户、订单日期、金额、状态。
需要查询、排序、分页、详情，并提供验收结果和生成文件。
```

### 从内部原型生成符合项目主题的代码

```text
使用 ERP Page Forge 插件，读取原型：
http://127.0.0.1:32767/start.html

按本机/内网原型模式，最多采集 5 页。
关联当前前端项目：D:\Projects\ERP
读取项目主题、组件库与技术栈，按原型生成项目代码包。
实现有依据的前端跳转、Tab、弹窗等，列出无法确认的交互。
不要覆盖原项目文件，返回代码包和待验证项。
```

原型地址也使用同一流程，把 URL 换成实际完整地址，例如 `http://prototype.example/erp`。电脑须能连接所在网络或 VPN，并解析该域名。目录也须换成本机真实前端项目根目录，根目录应有 `package.json`。

### 原型需要登录

```text
使用 ERP Page Forge 采集这个内部原型，需要手动登录。
请弹出采集浏览器，我登录后再开始采集。
地址：http://实际原型主机/原型路径
```

插件会打开独立的采集浏览器。用户完成登录后，点击右上角“登录完成，开始采集”。这不是平时浏览器的登录会话，Cookie 不会随产物导出或持久化。跳转到其他内网认证源当前可能被阻止，须另行适配。

### 只提取数据和主题

```text
使用 ERP Page Forge 采集这个原型，先不调用 AI 生成。
导出页面数据、主题和原型交互关系，告诉我哪些内容需要人工确认。
地址：http://实际主机/原型路径
```

### 在对话中应看到什么

正常流程是：AI 调用采集工具 → 返回页面、主题和交互统计 → 调用生成工具 → 返回代码包或 HTML、报告及本地产物路径。需要登录时插入手动登录步骤。若执行失败，AI 应说明失败原因；生成或工具执行成功不等于目标项目构建、交互和视觉效果验收通过。

## 方式二：打开 Forge Studio 网页操作

在 DSH 对话中输入：

```text
打开 Forge Studio，使用当前会话模型。
```

AI 调用插件的启动工具，在你的电脑上启动本地服务，并返回类似 `http://127.0.0.1:53163/` 的链接。端口会自动选择，请使用本次返回的地址，不要记住示例端口。

打开网页后有三个主要入口：

| 入口 | 适用任务 |
| --- | --- |
| 模板库 | 选择已有 ERP 模板，通过指令生成页面 |
| 设计台 | 从设计截图、HTML 或 Axure 导出目录进入 |
| 参考网页 | 输入公开、本机或内网原型 URL，采集主题和页面关系，按项目生成代码 |

### 参考网页的操作步骤

1. 访问方式选择“本机 / 授权内网原型”，输入包含 `http://` 或 `https://` 的完整地址。
2. 设置最多页面数；需要登录时勾选“手动登录后采集”。
3. 希望按现有项目生成时，填写本机前端项目的绝对目录。留空可继续静态还原。
4. 点击“采集网页”，查看截图、项目主题来源、页面数和交互清单。
5. 可直接导出页面数据、主题、原型数据或完整包。这一步不调用 AI。
6. 选择生成方式：“静态 HTML/CSS”或“按项目主题生成代码包”，填写补充要求并生成。
7. 查看结果和报告。项目代码模式下，预览是代码包说明；下载后在目标项目中审阅、构建和测试。

工作区用于组织不同任务，运行记录与下载入口在“产物与日志”中。生成代码包不直接覆盖原项目。

## 模型如何自动接入

通过 DSH 对话调用插件时，插件获取当前会话的提供方和模型标识，经 DSH 宿主服务调用。通过插件启动 Studio 时，Studio 的 AI 按钮使用启动时选择的同一模型，无需重复输入 API Key。

- 用户甲选择 gpt-6.1-sol，就使用用户甲已配置的该模型。
- 用户乙选择另一款支持图片的模型，就使用用户乙自己的模型与账号。
- 切换会话模型后，需要重新启动 Studio，已启动实例不会自动切换。
- 仅打开本地网页不能发现任意 AI 软件中的模型；该自动接入依赖 DSH 插件启动流程。
- 从命令行单独运行 Python Studio，不会自动继承当前 DSH 会话模型，需要独立配置或改为通过 DSH 启动。

在 Studio 上点击 AI 生成时，参考截图、采集内容和有限项目主题源码会发送给该模型；内部资料应使用已获授权的模型服务。

## 为什么是本机网页

Forge Studio 是插件的操作界面。`127.0.0.1` 表示使用者自己的电脑，不是外网网站，也不是作者的服务器。每个人安装后，服务与产物都在各自电脑上。别人不能直接使用你返回的本机地址；他们需要在自己的 DSH 中启动。

插件卸载或宿主结束会影响本地服务。若旧地址打不开，在 DSH 对话里重新请求“打开 Forge Studio”，使用新返回的链接。

## 当前边界

- 此安装包用于 DSH，其他 AI 工具需要适配，不能直接安装该包。
- 原型交互以可读取声明和导航关系为依据，不自动执行真实系统的提交、保存、删除或审批。
- 生成代码不包含推断出来的真实后端权限和业务规则。无接口契约时使用模拟数据或待接入适配层。
- 真实项目的组件 API、路由、主题引用、编译和交互需要在目标项目中验证。
- 更详细的原型类型、采集范围和依赖准备见 [原型采集说明](web-capture.md)。
