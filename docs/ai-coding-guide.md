# AI Coding 使用说明

> 面向使用者。目标是让你在 **5 分钟内**用这个 Skill 生成第一个 ERP 页面。

如果你已经在 DSH 安装了插件，请优先阅读 [DSH 插件使用指南](dsh-plugin-usage.md)：可直接在 AI 对话中下达采集/生成任务，也可让 AI 启动本机 Forge Studio 网页操作，自动复用当前会话模型。下文主要介绍原始纯文本 Skill 用法，其输出边界不代表插件全部功能。

---

## 一、这个 Skill 是什么

`ERP Page Forge` 是一份**纯文本规范**，用来约束 AI Coding 工具生成 ERP 通用页面的方式。

它解决的问题不是「AI 会不会写页面」，而是「AI 每次写的页面都不一样」：

| 没有 Skill | 有 Skill |
|---|---|
| 每次都要在 prompt 里写一遍"要分页、要排序、要空状态" | 规范里写死了，不用重复交代 |
| 金额对齐方式、状态颜色、间距全靠 AI 随缘 | 统一设计令牌，跨页面完全一致 |
| 漏了二次确认、漏了空状态，评审时才被发现 | 交付前对照自查清单逐条核对 |
| 换个人生成，风格就断层 | 换人、换工具、换模型，产物风格不变 |

**它不做什么**（边界要清楚）：

- 不连接任何后端、不做数据持久化、不发网络请求
- 不生成 React / Vue 组件，产物是单个自包含的 HTML
- 不替你决定业务字段，字段清单由你提供

## 二、安装

Skill 没有任何依赖，就是一个文件夹。

### 方式 A：Claude Code / CodeBuddy 等支持 Skill 目录的工具

把 `skill/` 整个目录复制到工具的 skills 目录：

```bash
# 用户级（对所有项目生效）
cp -r skill/ ~/.claude/skills/erp-page-forge/

# 或项目级（只对当前工程生效）
cp -r skill/ .claude/skills/erp-page-forge/
```

目录结构必须保持：

```
erp-page-forge/
├── SKILL.md                    # 主文件，工具靠它识别技能
└── references/
    ├── design-tokens.md        # 设计令牌
    ├── page-archetypes.md      # 页面原型库 A1–A6
    ├── data-contract.md        # 字段 → 控件 / 列的映射规则
    ├── entity-recipes.md       # 常见实体的预设配方
    └── quality-checklist.md    # 交付前自查清单
```

### 方式 B：任何其他工具（Cursor / Copilot / 网页版对话模型）

不需要安装。直接打开 `release/erp-page-forge-skill.md`（单文件合并版），**全文复制**，粘贴到对话开头，然后接上你的需求即可。

### 方式 C：不想装任何东西

打开本项目的 `index.html`，点右上角 **「复制 Skill 提示词」**，粘贴到任意 AI 对话窗口。

## 三、最小可用示例

### 例 1：生成一个销售订单列表页

```
请使用 ERP Page Forge Skill，用 A1 管理列表页原型，
生成「销售订单管理」页面。

实体：sales_order
字段：
- order_no    订单号      文本
- customer    客户名称    文本
- order_date  订单日期    日期
- amount      订单金额    金额（本位币）
- status      订单状态    枚举：草稿/待审核/已审核/已发货/已完成/已取消
- owner       业务员      文本
- delivery_dt 交付日期    日期

查询条件：订单号、客户、订单日期区间、状态、业务员
```

### 例 2：生成一个费用报销表单

```
请使用 ERP Page Forge Skill，用 A2 单据表单页原型，
生成「费用报销单」新建页面。

主表字段：申请人、所属部门、申请日期、费用类型、报销事由
明细字段：费用科目、说明、数量、单位、单价、金额、发生日期
需要：明细行可增删、自动合计、必填校验、底部吸附动作条
```

### 例 3：给现有页面补交互

```
请使用 ERP Page Forge Skill 的 quality-checklist.md，
审查我这段列表页代码，列出缺失的必备交互项，
然后按规范补齐。
```

### 例 4：在已有的项目里生成（跨技术栈）

**这是最推荐的用法。** 把项目路径告诉它，Skill 会先探测你的工程约定，再产出对齐的代码。

```
项目在 C:\Users\me\my-app（React 19 + Redux Toolkit + CRA）。

用 ERP Page Forge 生成 A1 管理列表页「销售订单管理」，
页面放 src/pages/SalesOrder/，数据层放 src/store/modules/。

实体 sales_order，字段：order_no(订单号/编码)、customer(客户/文本)、
order_date(订单日期/日期)、amount(订单金额/金额)、status(状态/枚举)、
owner(业务员/文本)。

要求：按我项目的现有约定写（状态用项目已有的 Redux Toolkit，不要另起 useState），
色值用我项目已有的设计令牌，最后跑一次 npm run build 确认能编译通过。
```

生成前它会先读你的 `package.json`、构建配置、目录树和 2–3 个现有源文件，
产出一张「项目约定画像」——**框架 / 语言 / 状态管理 / 样式方案 / 目录 / 命名 / 路径别名 / 是否已有设计令牌**。

已经实测验证过的技术栈：

| 技术栈 | 实测结果 |
|---|---|
| React 19 + JS + Redux Toolkit + CRA | 16 个文件 / 2804 行，`react-scripts build` 通过 |
| Vue 3.5 + TS + Pinia + Vite + CSS Modules | 8 个文件 / 1355 行，`vue-tsc --noEmit` 零错误 + `vite build` 通过 |

两条不必写进需求里的提醒（Skill 会自己处理）：
- **不必指定"用 useState 还是 Redux"** —— 它会读你的项目然后跟着走
- **不必担心色值冲突** —— 项目已有设计令牌时它会整表替换，不会把外来主色硬套进来

## 四、怎么把字段说清楚

Skill 靠 `data-contract.md` 把字段类型映射成控件和列格式。你只要**说对类型**，剩下的自动处理：

| 你说的类型 | 生成的控件 / 列格式 |
|---|---|
| `文本` | 左对齐文本；长文本超长省略 + title 悬浮 |
| `编码` | 等宽字体，不折行 |
| `金额` | 千分位 + 右对齐 + 等宽数字 + `¥` 前缀 |
| `数量` | 右对齐等宽；带单位时单位单独一列 |
| `日期` | `YYYY-MM-DD`；区间查询用双输入框 |
| `百分比` | 保留 1 位小数 + `%` |
| `枚举` | 彩色状态胶囊（语义色由枚举值决定） |
| `布尔` | 勾选图标，不用文字 |
| `人员` | 姓名 + 部门副标题两行 |
| `引用` | 编码 + 名称两行显示，编码灰色 |

**枚举值要给出语义色等级**，否则 Skill 会按默认灰蓝处理：

```
status 订单状态：枚举
  草稿=中性、待审核=提醒、已审核=进行中、已发货=进行中、
  已完成=成功、已取消=失效
```

如果没写，可以直接说「按状态语义自动分色」，Skill 会按常见约定推断。

## 五、生成后你需要改什么

产物是**可直接运行**的。要接真实数据，通常只改两处：

**1. 数据源**

```js
// 生成物里是这样
const ROWS = [ /* mock 数组 */ ];

// 换成接口
async function loadRows() {
  const res = await fetch('/api/sales/orders?' + new URLSearchParams(query));
  const json = await res.json();
  ROWS = json.data; renderTable();
}
```

**2. 动作回调**

```js
// 生成物里是 toast 占位
function onBatchApprove() { toast('已提交批量审核（示例）'); }

// 换成真实调用
function onBatchApprove() {
  fetch('/api/sales/orders/batch-approve', {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({ ids: selected })
  }).then(r => r.json()).then(() => { loadRows(); });
}
```

**不用改的**：CSS、设计令牌、查询区结构、表格渲染逻辑、分页组件、排序逻辑、空状态。

## 六、常见问题

**Q：生成出来的页面样式和我们的设计系统不一致怎么办？**
改 `references/design-tokens.md` 里的 CSS 变量，把它替换成公司设计系统的 token。改一处，之后所有页面自动跟随。

**Q：能用 Vue / React 吗？**
当前版本的产物是原生 HTML。如果要组件化，把生成的 HTML 当作**结构参考**，让 AI 按同样的区块顺序和交互清单转写成组件 —— 规范本身与框架无关。

**Q：为什么坚持零外部依赖？**
一是可断网运行、可离线演示；二是避免引入未经合规报备的外部服务。如果确实需要引入公司内部的组件库 CDN，改 `SKILL.md` 里的约束条款即可，但要自行完成合规报备。

**Q：生成的表格没有虚拟滚动，数据量大了会卡怎么办？**
默认面向「分页 10-50 条」的常规后台场景。如果确实需要虚拟滚动或大数据量渲染，这是超出当前 Skill 范围的定制需求，建议作为单独原型补充进 `page-archetypes.md`。

**Q：可以生成手机端页面吗？**
不可以。当前 6 个原型全部针对桌面端 ERP 后台。移动端是另一套交互范式，需要另建原型库。

**Q：AI 生成时漏了某些交互怎么办？**
这正是 `quality-checklist.md` 的用途。让 AI 在交付前逐条核对，或者生成后让 AI 对照清单自查一遍。清单里的项都是可验证的（有 / 没有），不是主观判断。

**Q：mock 数据会不会混进真实数据？**
目前靠规范约束 + 人工审核。生产使用时建议在 CI 里加一道正则扫描，禁止产物中出现真实客户名与真实编码段（本项目的 `build/check_pages.py` 就是这类扫描的最小实现，可参考）。

**Q：点了「AI 识别」报错「模型接口不可达」，怎么查？**
先读日志里那三行：错误句、建议、通道信息（会列出实际走的是代理还是直连、host、用时 / 超时上限）。
再点右栏「自检」，它按 `配置 → DNS → 端口 → 鉴权 → 真调一次模型` 逐步给结论：

| 报的什么 | 真正的原因 | 怎么办 |
|---|---|---|
| 读超时 | 模型比上限慢（图越复杂越慢） | 调大 `FORGE_AI_TIMEOUT`（例 `600`）后重启服务 |
| 连接超时 / 连接被拒绝 | 网络或代理不通 | 先试 `FORGE_AI_NO_PROXY=1`；再核对 base 地址 |
| HTTP 401 / 403 | 密钥不对，或密钥与 base 地域不匹配 | 北京的 key 别配上海的 base |
| HTTP 404 / 400 | 模型名不存在或没开通 | 核对 `FORGE_AI_MODEL` |
| 不是可用的 JSON | 输出被 `max_tokens` 截断 | 调大 `FORGE_AI_MAX_TOKENS`（例 `8192`） |

回归用例在 `python build/check_ai.py`（本地假模型服务，不碰外网、不用真密钥）。

## 七、踩坑记录

以下是实际使用中遇到过的坑：

1. **别一次让 AI 生成 3 个页面。** 上下文里塞多份规范后，AI 会串原型 —— 把 A5 的三栏布局用进 A3。一次一个页面，质量最稳。

2. **枚举值不给语义色，AI 会全部用灰。** 至少标出「成功 / 失败 / 提醒」三类，页面才有信息层次。

3. **字段名用 snake_case，不要用中文 key。** 生成物里 `row.order_no` 比 `row['订单号']` 好维护得多。

4. **原型编号要显式说。** 不说的时候 AI 会自己选，可能给「订单管理」选成 A4 看板，而你要的是 A1 列表。

5. **`references/` 不能只复制 `SKILL.md`。** 主文件只是索引，真正的细节在 6 个参考文档里。少复制一个，对应维度就会退化。

6. **在已有项目里用时，务必给出项目路径。** 不给路径，AI 只能产出零依赖单文件 HTML，
   跟你的工程体系对不上；给了路径，它会先探测约定（框架 / 状态管理 / 样式方案 / 已有令牌）再动手。
   
7. **跨栈产出后一定要让它跑一遍编译验证。** "代码写完了"和"能编译"是两回事 ——
   React 要 `npm run build`，TS 要 `vue-tsc --noEmit`。实测中这一步确实抓出过问题，别省。
   
8. **项目已有设计令牌时，明确说"用我们自己的令牌"。** 否则可能被 Skill 的默认主色覆盖，
   新页面与项目其它页面会出现肉眼可见的色差，评审时会被指出来。
   
9. **截图识别失败时，先分清是「哪一种不通」。** 模型接口不可达有四种完全不同的原因 ——
   读超时（模型慢，图越复杂越慢）、连接超时（网络或代理不通）、密钥或模型名不对、输出被截断。
   Studio 的「自检」按钮会把 配置 → DNS → 端口 → 鉴权 → 真调一次模型 逐步报出来；
   「AI 识别」失败时日志里也会打出实际走的通道（代理还是直连）、host、用时与超时上限。
   最常见的假故障是服务继承了不通的环境代理，加 `FORGE_AI_NO_PROXY=1` 直连即可排除。
   2026-10 那份「VLM 结构化通道」升级方案原本被误粘在第 9 条下面，已归档到
   `vision-vlm-upgrade-plan.md`（其中大部分已落地）。

## 八、扩展新原型

需要新增一类页面（比如「树形组织选择器」）时：

1. 在 `references/page-archetypes.md` 里加一节 `A7 · 原型名`
2. 画出骨架图（区块自上而下的顺序），标注哪些区块不可省略
3. 写交互清单，每条都要是**可验证**的（"点击表头在升序→降序→无之间循环"，而不是"排序体验好"）
4. 在 `references/design-tokens.md` 里补充该原型特有的令牌（如果有）
5. 生成 1 个示例页面放进 `templates/`
6. 跑 `python build/check_pages.py` 确认新页面通过校验
7. 更新 `tests/test-cases.md` 的覆盖率统计
