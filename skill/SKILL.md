# ERP 通用页面铸造器 · ERP Page Forge

## 0. 一句话定位

**ERP 后台 80% 的页面，都是同一批骨架的排列组合。** 这个 Skill 把这批骨架沉淀成"页面原型库 + 字段配方 + 设计令牌"，让 AI 一次对话就能产出**能跑、能用、风格统一**的 ERP 页面，而不是每次从零画表格。

**入口隔离（优先于下文原型规则）：A1–A6 仅固定内置模板；上传截图 → AI 语义/布局识别 → `kind:screenshot` 独立契约 → `screenshot_render.py` → 人工复核 → 保存新模板。截图入口不选 A1–A6、不补配方字段、不用默认主题/外壳；下文 PageSpec、配方与原型规则只适用内置生成。截图识别只保留可见结构，无法推断的交互明确待确认；禁止整图铺底冒充页面。

---

## 1. 什么时候用 / 什么时候别用

**用：** ERP 后台六类高频页面（见第 5 节 A1–A6）；需求评审阶段"先看页面再写代码"；**用户丢一张后台截图说"照这个做"**（见 `references/generation-layer.md` 第 7–8 节）；**用户给的是 Axure 原型**（读产品经理的标注与站点地图，比截图更准，见 `references/axure-entry.md`）。

**别用：** C 端营销页/落地页（审美体系不同）· 需要真实接后端接口与数据落库（只产前端 + mock 数据，接口层留 TODO）· 涉及真实生产敏感数据的填充（见第 9 节安全红线）。

## 2. 生成前澄清：把描述归一成 PageSpec 并回显确认（闸门 1）

不同的人描述同一个需求，产出差很远 —— 根因是没有**输入契约**。所以生成前先把需求归一成
`PageSpec`（结构定义见 `spec/page-spec.schema.json`），再回显给用户确认。

| # | 问题 | 默认值（用户没答就按这个走） |
|---|---|---|
| Q1 | **业务实体是什么？** | 从页面名提取；提取不到 → 「业务单据」 |
| Q2 | **要对它做哪些动作？** | 列表页：查询 + 新建 + 编辑 + 导出 + 批量操作 |
| Q3 | **有哪些状态、怎么流转？** | `草稿 → 已提交 → 已生效`，异常态 `已驳回 / 已作废` |
| Q4 | **用哪个原型？**（决定骨架） | 按页面名关键词映射，见 `spec/page-spec.schema.json` 的 `defaults.Q4` |
| Q5 | **产出到哪个技术栈？** | 给了项目路径 → 探测；否则产出单文件 HTML |

**必须回显**：每个默认值标出处（`inferred` / `fallback` / `recipe`），用户可逐条改，缺项不静默猜。
> 例：`原型 → A5 审批工作台（inferred：页面名含"审批"）`；`状态机 → 待审批 → 流转中 → 已通过/已驳回（fallback）`

若用户只给了页面名（如"帮我做个采购申请单页面"），**不要反问**，直接填默认 + 回显 + 生成。

## 3. 工作流（7 步，不要跳步）

### Step 0 · 澄清并落成 PageSpec（闸门 1）

按第 2 节把需求归一成 `PageSpec`，缺项填默认值后**按出处回显**给用户确认；每个默认值带
`provenance`（`user`/`recipe`/`inferred`/`fallback`）—— 默认值可见、可改、有出处是满意度的前提。
字段的**业务语义**不写进 schema（结构稳定、语义多变），留在 `references/` 由人读。

### Step 1 · 探测目标项目约定（仅当目标是已有项目）

先读 `package.json`、`README`、构建配置、`src/` 目录树和 2–3 个现有源文件，落成一张**项目约定画像**：
框架与版本 / 语言 / 状态管理 / 路由 / 样式方案 / 目录 / 命名 / 路径别名 / **项目是否已有自己的设计令牌** / 验证命令。

- 目标是空项目、或用户只要一个独立页面 → 直接跳到 Step 2，产出默认的单文件 HTML。
- 探测不到约定 → 按本 Skill 默认值走，并在回复里写明"我按 X 假设的，与你们约定不符告诉我改"。
- **完整探测清单与冲突裁决规则见 `references/stack-adaptation.md` 第 1–2 节。**

### Step 2 · 判定页面原型（决定骨架）
读第 5 节的**页面原型库**，从 A1–A6 里选 1 个主原型写进 `PageSpec.archetype`。复杂页面 = 1 个主原型 + 若干延伸区（写成 `extends`，例如"列表页 + 右侧详情抽屉"）。

### Step 3 · 拉字段配方（决定列和表单项）
读 `references/entity-recipes.md` 找到对应实体的**标准字段配方**：主键/编码规则/核心业务字段/状态字段/审计字段/金额与数量精度。
- 实体不在配方表里 → 按配方表的**通用字段骨架**（编码、名称、类型、状态、负责人、组织、创建人、创建时间、备注）自行扩展。
- 字段顺序遵循 ERP 惯例：**先身份后业务，先编码后名称，先金额后时间**。
- 落进 `PageSpec.fields`，每项标 `provenance`。

### Step 4 · 排状态机与动作按钮（决定交互）
把 Q3 的状态写进 `PageSpec.statusMachine`，并为每个状态确定"当前状态可执行的动作"（`actions[].allowedStates`）：

| 当前状态 | 可执行动作 | 动作后的状态 |
|---|---|---|
| 草稿 | 提交、删除、编辑 | 已提交 / — |
| 已提交 | 审核通过、驳回、撤回 | 已生效 / 已驳回 / 草稿 |
| 已生效 | 变更、作废 | 变更中 / 已作废 |

**按钮可见性必须跟着状态走**（已生效的单据不再显示"编辑"，显示"变更"），这是 ERP 页面专业度的分水岭。

### Step 5 · 造 Mock 数据（可运行的前提）
严格按 `references/data-contract.md`：
- 数量：列表页 ≥ 12 行（够触发分页），看板 4 张 KPI + 12 个趋势点，审批待办 ≥ 6 条
- 全部为**虚构脱敏数据**：公司名加"（示例）"、编码走 `规则-年份-序号`、人名用"张明/李静"这类通用名、金额数量级合理（不要出现 999999999）
- 金额统一 `¥1,234,567.89`（两位小数 + 千分位），数量按物料单位保留 0–3 位，日期统一 `YYYY-MM-DD`
- 数据内部要**自洽**：合计 = 明细之和，状态标签 = 可执行动作链，客户/供应商名在全站复用一致

### Step 6 · 产出 + 自检 + 验收（闸门 3）

按第 4 节输出规范产出代码，逐条过第 8 节自检清单，复核第 9 节安全红线。任何一项没过自己修，不要交给用户。

**然后跑四类断言验收 —— 没过闸门不许说"已完成"：**

```
python build/verify_acceptance.py --spec <spec> --plan                 # 生成前：把验收项列给用户
python build/verify_acceptance.py --spec <spec> --artifact <产物> \     # 生成后：跑四类断言
    --root <构建产物目录> --route <路由> --out build/acceptance.json
python build/build_report.py --report build/acceptance.json --out build/acceptance-report.html
```

四类断言及其判据来源：
**契约** — 声明过的字段/动作/状态/原型必备要素一个不少（`spec/archetypes.json` + PageSpec）；
**渲染** — 1280px 横向溢出 0 · 脏值 0 · 脚本零错误 · 非白屏（无头浏览器真实渲染）；
**交互** — 真实点按钮：筛选真的会筛、同意真的减待办、驳回必须填原因（同源 iframe driver）；
**数据** — 合计 = 明细之和、待办计数 = 列表条数、状态枚举覆盖（同上）。

产物单元常跨目录（页面组件 + store slice）→ `--artifact` 可重复传。
硬性项全过才算交付；**拿不到浏览器、或控件无法自动驱动的项标 `unsupported`（需人工确认），不许当通过**。
失败则自动返修最多 2 轮，仍失败交人工并附失败清单。另外仍需跑通目标栈编译级验证
（React → `build`；Vue/TS → `vue-tsc --noEmit` + `build`），验证线见 `references/stack-adaptation.md` 第 4 节。

### Step 7 · （可选）走确定性渲染路径

不想每次让模型重写骨架时，用生成层：`build/forge.py` 吃 `PageSpec` 渲染成单文件 HTML
（同一 spec 两次生成**逐字节一致**）；已有页面用 `build/reverse.py` 反抽出 `PageSpec`
（"照这个做，字段换成我的"）。骨架覆盖 A1–A6 全部原型；`custom` 诉求或未知原型明确回退全量生成。
详见 `references/generation-layer.md`。

## 4. 输出规范

### 默认目标：单文件 HTML（零依赖、双击即开）
- 一个 `.html` 文件内包含 HTML + CSS + JS，**不引任何 CDN、不发任何网络请求**
- 图表用原生 SVG 或 CSS 手绘，不引图表库
- 图标用手写内联 SVG 或 CSS 几何图形，不引图标字体
- 打开即渲染，无需构建、无需 npm

### 在已有项目里产出时（用户指定了目标项目或技术栈）

**先做 Step 1 的探测，再按四层取舍产出。** 冲突一律按层裁决，不要整体倒向某一方：

| 层 | 内容 | 裁决 |
|---|---|---|
| ① 业务规范层 | 原型骨架、字段配方、状态机、Mock 数据规范、交互要求 | **Skill 优先**（本 Skill 的价值所在） |
| ② 工程实现层 | 语言、状态管理、路由、样式方案、目录、命名、别名、构建 | **目标项目优先**（Skill 不得强加偏好） |
| ③ 视觉令牌层 | 色值、字号、间距、圆角、布局尺寸 | 项目已有令牌 → **整表服从项目**；**用户给了参考图 → 整表服从参考图**（`PageSpec.tokens` 注入，浅色侧栏自动翻转文字色）；都没有 → 落 Skill 默认 |
| ④ 防坑规则层 | `nowrap`、`minmax(0,1fr)`、`tabular-nums`、数字右对齐、表格自滚 | **无条件保留**（踩出来的经验，与栈无关） |

拆分**粒度**由本 Skill 定（查询区 / 数据表格 / 抽屉 / 状态标签必须分开）；
拆分后的**命名与放置位置、状态管理写法、样式方案**全部跟目标项目。
小程序 / 移动端：卡片列表替代表格，筛选收进顶部抽屉，操作收进底部弹层。

> 探测清单、令牌映射表、各栈产出契约与验证线，见 `references/stack-adaptation.md`。

## 5. 页面原型库 A1–A6

> 详细结构与交互清单见 `references/page-archetypes.md`。视觉实现必须遵循 `references/design-tokens.md`。

| 编号 | 原型 | 一句话骨架 | 典型页面 |
|---|---|---|---|
| **A1** | 管理列表页 | 面包屑 + 查询区 + 工具条 + 数据表格 + 分页 | 销售订单、客户档案、物料列表 |
| **A2** | 单据表单页 | 表头字段分组 + 明细行表格 + 合计 + 底部动作条 | 采购申请单、报价单、入库单 |
| **A3** | 主数据详情页 | 头部摘要 + Tabs（基本信息/关联单据/变更记录） | 物料主数据、客户 360 |
| **A4** | 运营看板页 | KPI 卡片组 + 趋势图 + 排行/预警列表 | 库存健康度、产销存看板 |
| **A5** | 审批工作台 | 左侧待办/已办 + 中间单据详情 + 审批轨迹时间线 + 审批动作 | 待办中心、合同审批 |
| **A6** | 台账/对账页 | 复杂多列 + 汇总行 + 期间选择 + 导出/打印 | 客户对账单、总账余额表 |

**组合规则**：A1 + 右侧 `Drawer`（详情抽屉）= 最常见的 ERP 主数据页；A6 + 期间选择器 = 报表页；A5 内嵌 A3 = 审批看详情。

## 7. 生成结果必须"能跑"的最低要求

同时满足这 5 条才算合格：
1. **筛选真的会筛**：输入/下拉改变后，表格行数或内容随之变化（纯前端过滤）
2. **分页真的会翻**：页码可点，切换后内容变化，且显示"共 N 条"
3. **排序真的会排**（列表页）：点表头按该列升降序，表头有方向指示
4. **状态真的会变**：操作后行的状态标签、可用按钮跟着变（如"提交"后草稿变已提交）
5. **反馈真的会给**：任何操作都有 Toast 或行内提示，不留"点了没反应"的死按钮

## 8. 自检清单（产出前逐条过，24 项）

> 「结构 / 数据格式 / 视觉 / 跨栈」的大部分已由 `spec/archetypes.json` 做成**可执行断言**，跑 Step 6 的验收就自动查。
> 本清单用于**人工复核机器查不出的部分**（业务合理性、手感、故事性）。

**结构** ① 骨架是否完整（查询/工具条/表格/分页一个不缺）？② 面包屑三级？③ 筛选无结果有空状态？
**数据** ④ 字段来自配方且用业务术语（`订单号` 而非 `orderId`）？⑤ 金额 `¥1,234,567.89`、日期 `YYYY-MM-DD`、数量带单位？⑥ 合计 = 明细之和（自己核一遍）？⑦ 有 >0 条预警/异常数据让页面"有故事"？
**交互** ⑧ 筛选/分页/排序真的生效（第 7 节 1–3 条）？⑨ 状态机与按钮可见性一致？⑩ 未勾选时批量操作给提示而非静默失败？⑪ 必填校验有红字 + 阻止提交？⑫ 抽屉/弹窗可关闭（遮罩/按钮/Esc）？
**视觉** ⑬ 色值全部来自令牌，无 `#333` `blue` 这类随手值？⑭ 数字右对齐、文字左对齐、状态居中？⑮ 状态标签是胶囊 + 语义色？⑯ 1280px 不横向滚动？⑰ 数字列 `nowrap`（`2026-09-17`、`¥1,286,400.00` 不折行）？⑱ 弹性列 `minmax(0,1fr)` 而非裸 `1fr`？
**工程与安全** ⑲ 零外部依赖、零网络请求（打开即用）？⑳ 全虚构脱敏数据，无真实客户名/工号/手机号/真实金额？
**跨栈**（已有项目必查，见 `references/stack-adaptation.md`）㉑ 生成前**实际读过**项目配置、目录树与 2–3 个现有源文件并落成约定画像？㉒ 项目已有令牌时**整表替换**、零原色值残留、零硬编码 hex？㉓ 跑通目标栈编译级验证（React→`build`；Vue/TS→`vue-tsc --noEmit`+`build`）并做过一次真实渲染检查？
**交付闸门** ㉔ 落成 `PageSpec`（默认值都标了出处）并跑通四类断言验收？硬性项全过、`unsupported` 项都已解释？验收报告给用户看了？

> 26 条可执行检查动作（A–F 六组）与 100 分制打分标准见 `references/quality-checklist.md`。

## 9. 安全红线

- **绝不**用真实客户信息、未脱敏生产数据、公司内部敏感数据去填充生成页面。所有示例数据必须虚构。
- 生成的页面**只做前端展示**，不得内嵌任何外部 AI 平台接口、第三方埋点或数据上报。
- 若用户要求接入外部接口 / 第三方服务，先提示"需提前合规报备"，并只输出 `TODO: 接入合规报备后的内网接口` 占位。
- 任何"生成类"能力（如 AI 自动填单、智能补全）必须保留**人工复核**环节：页面上给出"待人工确认"标识与确认按钮，禁止自动提交。

## 10. 常见错误（反例）

| 反例 | 为什么错 | 正确做法 |
|---|---|---|
| 直接吐一个静态表格截图式页面 | 不能交互，评审时一问就露 | 必须带筛选/分页/排序 |
| 用 `#409EFF`、`blue`、`#333` 等随手色值 | 页面之间风格不统一 | 只允许用第 6 节令牌 |
| 编造 9999999 元、客户名"某某科技有限公司"堆 20 行 | 一眼假，失去说服力 | 数据量级合理、名字错落、含异常态 |
| 已生效单据还显示"编辑/删除" | 违反业务规则，ERP 人一眼挑错 | 按钮跟着状态机走 |
| 表格里所有列左对齐 | 数字列无法快速比对 | 金额数量右对齐、时间居中 |
| 引 Element UI / ECharts CDN | 内网打不开，Demo 现场挂 | 零依赖，SVG 手绘 |
